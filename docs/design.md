# 词稿产品与技术设计

## 发布范围

词稿是一个 Windows 桌面提示词编辑器。用户能在同一个程序里完成模型配置、起草、改写、对照、保存、查找、复用和导出。接入云端或本机模型后即可开始使用。

| 区域 | 发布功能 |
| --- | --- |
| 首次运行 | 进入示例草稿或设置向导，选择预设服务、填写 API Key，测试连接并显示可操作的失败原因 |
| 工作台 | 新建与重命名草稿，自动保存，改写、取消、重试，预览、编辑和对比优化稿，复制与导出 Markdown 或纯文本 |
| 项目与资料库 | 项目分组、搜索、收藏、模板应用、最近打开。删除项目时展示草稿数量并要求确认 |
| 版本历史 | 保存每次成功改写的原文、结果、模型和时间，支持对照。恢复旧稿创建新版本，保留已有记录 |
| 设置 | DeepSeek 与智谱 GLM 预设、活动模型切换、连接测试、浅色／深色／跟随系统、关于、自定义快捷键、窗口行为、开机自启 |
| 本地数据 | JSON 备份与恢复，选择文件时预检格式和数量，导入失败时保留现有数据，完整备份包含明文密钥，导出前提示保管 |

退出后保留草稿、版本和已保存的 API Key。当前模型选项会保存在本地。界面在提交前显示文本将发送到的端点。程序通过原生文件对话框选择导入或导出位置。

## 页面设计

把「词稿」做成编辑器式工作台。侧栏上方显示项目和草稿，下方固定显示模型、模板和设置。主区是一张可以左右对读的稿纸。视觉焦点是正在写的文字、版本变化和主操作。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 词稿             产品文案 / 首页标题                              │
├─────────────────┬──────────────────────────┬────────────────────────┤
│ 新建草稿        │ 原稿                     │ 优化稿   对比   复制   │
│ 搜索草稿        │                          │                        │
│                 │ 给一家独立书店写一条     │ 请为一家独立书店……     │
│ 工作台          │ 周末活动海报提示词。     │                        │
│ 资料库          │                          │                        │
│                 │                          │ 待确认问题（按需）      │
│ 项目            ├──────────────────────────┴────────────────────────┤
│   产品文案      │ 已保存 · 当前模型                       优化提示词 │
│ 模型 / 模板 / 设置│                                                  │
└─────────────────┴────────────────────────────────────────────────────┘
```

- 编辑器左右共用一条顶部基线，中间用细分隔线。版本历史从右侧打开，方便在当前稿件上下文中选择日期和对照。模型、模板和设置从侧栏切换到主区，保留当前草稿。
- 浅色主题使用浅灰工作区 #F6F7F8、白色编辑面、石墨正文 #20252B、次文字 #535D68、细分隔线 #DCE0E4、深灰蓝主操作 #384454。深色主题拥有对应的语义色和单独验证过的对比度。
- 界面使用 Inter，中文回退到微软雅黑或系统中文字体。标签 13px、编辑正文 16px、稿件标题 22px。编辑列左对齐，限制长段落行宽。变化视图用文字和颜色一起标记新增与删除。
- Naive UI 负责菜单、表单、抽屉、弹窗和反馈。应用自己控制留白、布局和主题。图标全用 Lucide SVG，功能按钮带文字或可访问名称。禁止 Emoji、颜文字和 Unicode 文本符号充当图标。
- 默认并排编辑，窄窗口收起侧栏并让原稿和优化稿上下排列。提供 Ctrl+N 新建、Ctrl+Enter 优化。中文输入法组词期间避免误触发提交。

### 状态

空白时提供真实示例入口。未配置模型时提供设置入口。改写时显示当前任务并允许取消，过期请求的结果不得覆盖已切换的稿件。发生超时、鉴权、连接或格式错误时显示具体问题和对应操作，保留原稿和最近一次成功结果。复制、保存和导出在界面上提供确认反馈。

## 工程边界

Vue 3、TypeScript、Vite、Naive UI 和 Lucide 负责 UI。Tauri 2 提供原生窗口和文件对话框。Rust 使用异步 reqwest 和 serde 调用 OpenAI 兼容的 Chat Completions 接口，以 SQLite 保存草稿、项目、版本和配置。数据库只在 Rust 侧访问。备份导入和版本保存使用事务，数据库按当前结构直接初始化。

| 范围 | 职责 |
| --- | --- |
| src/features/workspace | 编辑、请求状态和版本对照 |
| src/features/library | 项目、搜索、收藏和模板 |
| src/features/settings | 模型、外观和备份管理 |
| src/lib/tauri.ts | 类型化 IPC 调用 |
| src-tauri/src/commands.rs | 输入校验与错误转换 |
| src-tauri/src/optimizer.rs | 组装模型输入并校验改写结果 |
| src-tauri/src/model_client.rs | 请求、取消、超时、模型响应解析 |
| src-tauri/src/storage.rs | 关系表读写、增量保存和导入事务 |
| src/features/library/templates.ts | 模板页默认提供的优化模板 |

优化时将所选模板作为系统消息。模板使用 Mustache 的分隔符指令、originalPrompt 或 helpers.toJson 时先本地渲染，普通模板直接传递。模板中的三花括号原样插入文本，helpers.toJson 配合三花括号可插入安全编码的 JSON 字符串。用户提示词可以独立编辑，支持与系统提示词相同的 Mustache 渲染。用户提示词留空时，普通优化使用默认改写指令和 originalPrompt 字段，迭代继续发送原稿、上一版及修改意见。模型返回的非空文本直接保存为优化稿。API Key 按供应商配置和接口地址保存在本机 SQLite，由 Rust 读取。预设模型使用各自的官方 HTTPS 端点。只为本地界面配置实际使用的 Tauri 权限。

## 验收顺序

1. 先实现可运行的工作台，验证每种页面状态、中文输入法、键盘操作、字体、窄窗口和两套主题。用截图检查布局。
2. 跑通 DeepSeek 与智谱 GLM，验证取消、超时、重试及切换稿件后迟到响应。
3. 检查重启恢复、搜索、版本恢复、备份回导、损坏导入回滚和完整数据恢复。
4. 在干净 Windows 环境验证安装、启动和卸载。Gitee 发行版附源码、中文 README、许可证和 Windows 安装包。

模板按「基础」「上下文」和「迭代优化模板」分类。草稿页先选分类和模板，再选供应商与模型。上下文首轮使用所选模板。追问使用输入框旁所选的迭代优化模板，默认提供「小步迭代」，只发送当前优化稿和本轮意见，旧稿及追问意见在本地版本记录中保存。内置「小步迭代」的两段原文保存在 [上游模板资产](../src/features/library/upstream/README.md)，该资产附有来源和许可证。

通过侧栏新建草稿时，草稿默认未分配项目；从项目页新建的草稿直接归入对应项目。草稿页顶部可以分配或清除项目。未命名草稿首次点击优化时用原稿开头自动生成标题。

## 常规设置与窗口行为

- 常规设置按主题样式、窗口行为、自定义快捷键排序。主题选项使用 16px 图标与 6px 图文间距，统一 34px 控件高度。
- 应用内快捷键使用物理按键 code 保存，支持 Ctrl/Alt/Shift 组合；录制中暂停其他快捷操作，校验系统保留按键和应用内冲突。配置保存在工作区 SQLite，默认使用 Ctrl+N 和 Ctrl+Enter。运行 `node tests/shortcuts.mjs` 验证规则（Node 22.18+）。
- 关闭行为保存为 ask/hide/exit，默认值为 ask。标题栏、Alt+F4 统一触发关闭处理；确认框支持记住选择。保存失败不隐藏、不退出，隐藏前检查托盘可用性。退出前提示正在进行的优化任务会中断。
- 托盘提供打开与退出入口，左击重新显示并聚焦原窗口。单实例插件避免重复启动多个工作区实例。
- 开机自启使用 Tauri 官方插件查询和修改系统注册状态，不随工作区备份迁移，不在启动时擅自开启。

## 系统内置与用户模板

- 基础、上下文、迭代分类及七个默认模板定义在 `src/features/library/templates.ts` 与 `upstream/builtin-templates.json`，分类不能编辑或删除，系统模板只读查看与预览。
- SQLite 的 `templates` 只保存用户模板。使用和展示时合并代码内置模板，优先保留内置 ID，禁止用户保存、删除或覆盖系统模板。用户可以在任一分类中新建自己的模板。
- 使用 `node tests/templates.mjs` 验证内置只读、自定义内容保存及 ID 冲突保护。

## 自定义模型供应商

供应商选择页提供“自定义供应商”，按 OpenAI 兼容协议请求 `/chat/completions`，通过 `/models` 获取模型列表。用户填写接口基础地址、API Key 和模型 ID，官方网站可选。模型支持手动输入和接口获取；自定义配置与预设配置一样支持连接测试、编辑、删除及草稿页选择。身份使用 `preset-custom`，不会因接口地址变更而从供应商列表消失。

## SQLite 当前结构

数据库位于应用数据目录的 `prompt-draft.sqlite`，由 `src-tauri/src/schema.sql` 直接初始化。包含十张业务表与一张缓存表：

| 表 | 职责 |
| --- | --- |
| `projects` | 项目名称和创建、更新时间 |
| `drafts` | 草稿原稿、优化稿、项目归属、置顶与收藏 |
| `draft_versions` | 草稿版本正文、迭代意见、供应商和模型快照 |
| `template_categories` | 用户模板分类 |
| `templates` | 用户模板及系统、用户两段提示词 |
| `providers` | 供应商配置、默认模型、获取的模型列表及 API Key |
| `usage_records` | 请求结果、Token、接口范围和人民币费用快照 |
| `model_prices` | 内置、同步和用户覆盖价格 |
| `pricing_settings` | 汇率及价格同步状态 |
| `app_settings` | `preferences_json` 保存偏好，`ui_state_json` 保存当前稿件及侧栏展开状态 |
| `models_dev_cache` | models.dev 原始目录 JSON 与获取时间 |

日常保存通过 `workspaceChanges.ts` 计算实体差异，调用 `save_changes`，只传递变化的记录及删除 ID；Rust 在同一事务内更新相关表。UPSERT 对相同数据不执行写入。设置改变不会重写草稿，编辑草稿不重写其他草稿，未变化的版本记录也不写入。启动时将关系表组装为前端工作区，完整快照仅用于页面内状态和导入导出，不再作为数据库存储形式。

项目删除通过外键将草稿改为未分配，草稿永久删除则级联清除版本。模板分类可能指向代码内置分类，因此由 Rust 校验分类引用，并禁止用户覆盖内置 ID。供应商删除连同密钥一起生效，但请求记录保留独立的供应商 ID、名称和费用快照，不级联删除历史用量。

供应商名称、接口和密钥在 `providers` 同一行。Rust 查询工作区时明确选择非密钥字段，常规查询不包含 API Key；完整 JSON 备份由 Rust 直接写文件，包含 API Key 和全部 11 张表。更新配置时仅在接口地址未变时保留密钥，地址改变则清空；在请求时同时按 ID 与接口匹配密钥。

`model_prices.layer=base/override` 区分基础价格和用户覆盖；来源与同步时间直接保存在价格行。`usage_effective_prices` 是查询视图。价格、汇率、人民币成本用 TEXT 存储十进制数，Rust Decimal 计算；`cost_cny` 与 `cost_details_json` 一起保存历史金额，后续调价不重算已计价请求。Token 未提供保存 NULL，明确为零才保存 0。

数据库所有 `_at` 字段使用 Unix 毫秒时间戳。统计 IPC 保持秒级时间范围和时间展示，在 Rust 查询边界转换。原稿和优化稿在前端使用的模板及 API 协议保持不变。

测试阶段仅支持当前结构，不提供数据库迁移或旧版数据兼容；结构调整后直接重建测试库。系统模板始终从源码读取，不写入用户模板表。`cargo test` 与 `node tests/workspace-changes.mjs` 验证增量保存、事务回滚、密钥排除、删除关系及价格统计。

## 单窗口草稿并发

不同草稿可以独立发送优化请求，同一草稿处理中禁止重复发送。切换草稿或工具页面不终止请求，流式输出、取消和结果按草稿 ID 与请求 ID 隔离。侧栏中每个正在处理的草稿右侧显示加载动画。后台失败提示包含草稿名称；成功结果保留原有版本保护，编辑过的内容不会被覆盖。删除草稿或项目时取消涉及的请求，退出时处理全部请求，隐藏到托盘继续生成。完整备份和恢复仍需等待全部请求结束。不新增应用内并发数量上限，实际受供应商限制；不涉及多窗口同步。

## 草稿菜单与快捷键

标题菜单与右键菜单分别配置。右键菜单提供重命名、置顶、收藏、复制草稿、项目归属与删除；标题菜单提供重命名、置顶、收藏、版本历史、项目归属与删除。标题菜单与左侧右键菜单均显示已绑定操作的当前快捷键；按键仍作用于当前打开的草稿。复制草稿保留原稿、优化稿、项目归属，标题追加副本，不复制版本历史、收藏、置顶或活动请求，创建后打开副本。删除置于菜单末尾并保留确认。新增重命名 Ctrl+Alt+R、置顶 Ctrl+Alt+P、收藏 Ctrl+Alt+F、删除 Ctrl+Shift+Delete、复制草稿 Ctrl+Alt+C、版本历史 Ctrl+Alt+H。均可在设置中录制修改或恢复默认，全量检查快捷键冲突。快捷键仅作用于当前草稿，中文输入法组词、弹窗及快捷键录制时不触发；删除始终确认。


## 草稿页连续修改

草稿页首次展示原始需求输入区，生成成功后以单栏当前稿为主体，原始需求按需展开。底部固定修改意见输入框，所有模板生成的稿件均可继续修改，Ctrl+Enter 与按钮使用同一入口。保留现有预览、编辑、版本恢复、复制和导出。默认对比本轮修改前后，手动修改的正文在下一次成功生成时保留快照。

继续修改发送原始需求、当前稿、本轮意见及当前连续版本段的历史修改要求，发生冲突以最新意见为准。首次生成或恢复版本作为历史要求的分段边界；恢复后以恢复稿继续。上下文超过现有用户消息长度限制时报错，不静默截断。历史列表优先显示本轮修改要求。


### 先挑选初稿，再小步修改

生成首版后不自动进入迭代，底部保留原始需求、分类与基础模板选择，可以更换模板或再次生成。候选导航复用同原始需求下没有修改意见的生成版本，按生成顺序切换；切换前保存尚未记录的手动编辑稿。选定稿件后点击“基于此稿继续修改”，底部才切换为修改意见与迭代模板；可以返回挑选初稿。迭代状态按草稿独立保留于当前会话，重启后默认回到挑选阶段。切换候选不删除已有版本。


### 无需切换阶段的操作入口

取消进入迭代和返回挑选的阶段按钮。生成后顶部始终提供基础模板选择与“重新优化”，按原始需求生成另一候选；底部始终提供修改意见和迭代模板，基于当前显示的稿件继续修改。Ctrl+Enter 在无稿时生成初稿，有稿时提交修改意见。候选切换和版本保留规则不变。更换基础模板不清空尚未发送的修改意见。
