# 词稿产品与技术设计

## 发布范围

词稿是一个 Windows 桌面提示词编辑器。用户能在同一个程序里完成模型配置、起草、改写、对照、保存、查找、复用和导出。接入云端或本机模型后即可开始使用。

| 区域 | 发布功能 |
| --- | --- |
| 首次运行 | 进入示例草稿或设置向导，选择预设服务、填写 API Key，测试连接并显示可操作的失败原因 |
| 工作台 | 新建与重命名草稿，自动保存，改写、取消、重试，预览、编辑和对比优化稿，复制与导出 Markdown 或纯文本 |
| 项目与资料库 | 项目分组、搜索、收藏、模板应用、最近打开。删除项目时展示草稿数量并要求确认 |
| 聊天记录 | 每次成功优化及追问按消息保存，记录模板和模型；独立优化开启新上下文，旧记录可回看和复制 |
| 设置 | DeepSeek 与智谱 GLM 预设、活动模型切换、连接测试、浅色／深色／跟随系统、关于、自定义快捷键、窗口行为、开机自启 |
| 本地数据 | JSON 备份与恢复，选择文件时预检格式和数量，导入失败时保留现有数据，完整备份包含明文密钥，导出前提示保管 |

退出后保留草稿、聊天记录和已保存的 API Key。当前模型选项会保存在本地。界面在提交前显示文本将发送到的端点。程序通过原生文件对话框选择导入或导出位置。

## 页面设计

把「词稿」做成以当前稿为中心的工作台。默认显示模板优化的双栏编辑区；连续对话在空白时显示应用标志、引导文案与底部输入框，生成后显示单列消息流，原始需求按需展开。侧栏管理项目和草稿，下方提供模型、模板和设置。

- 模板优化采用左右对照，连续对话采用单列消息流，顶部切换模式。双框底部选择模板、供应商和模型并确认优化；聊天底部输入消息并发送。右侧支持预览、原文、对比、复制、导出和放大，不提供版本入口。每次重新优化在聊天中保留完整问答，并开启独立上下文。
- 浅色主题使用浅灰工作区 #F6F7F8、白色编辑面、石墨正文 #20252B、次文字 #535D68、细分隔线 #DCE0E4、深灰蓝主操作 #384454。深色主题拥有对应的语义色和单独验证过的对比度。
- 界面使用 Inter，中文回退到微软雅黑或系统中文字体。标签 13px、编辑正文 16px、稿件标题 22px。编辑列左对齐，限制长段落行宽。变化视图用文字和颜色一起标记新增与删除。
- Naive UI 负责菜单、表单、抽屉、弹窗和反馈。应用自己控制留白、布局和主题。图标全用 Lucide SVG，功能按钮带文字或可访问名称。禁止 Emoji、颜文字和 Unicode 文本符号充当图标。
- 默认单栏阅读，窄窗口收起侧栏、工具栏换行，保持输入框与正文分区。默认 Ctrl+N 新建、Enter 提交（优化／发送），Shift+Enter 与 Alt+Enter 换行。两组换行快捷键分别自定义，备用键允许清空；快捷键失焦自动保存，统一检查冲突，支持单键与组合键，普通单键窗口操作不在文字输入时触发。中文输入法组词期间避免误触发提交。

### 状态

空白时提供真实示例入口。未配置模型时提供设置入口。改写时显示当前任务并允许取消，过期请求的结果不得覆盖已切换的稿件。发生超时、鉴权、连接或格式错误时显示具体问题和对应操作，保留原稿和最近一次成功结果。复制、保存和导出在界面上提供确认反馈。

## 工程边界

Vue 3、TypeScript、Vite、Naive UI 和 Lucide 负责 UI。Tauri 2 提供原生窗口和文件对话框。Rust 使用异步 reqwest 和 serde 调用 OpenAI 兼容的 Chat Completions 接口，以 SQLite 保存草稿、项目、聊天消息和配置。数据库只在 Rust 侧访问。备份导入和消息保存使用事务，数据库按当前结构直接初始化。

| 范围 | 职责 |
| --- | --- |
| src/features/workspace | 编辑、请求状态和聊天记录 |
| src/features/library | 项目、搜索、收藏和模板 |
| src/features/settings | 模型、外观和备份管理 |
| src/lib/tauri.ts | 类型化 IPC 调用 |
| src-tauri/src/commands.rs | 输入校验与错误转换 |
| src-tauri/src/optimizer.rs | 组装模型输入并校验改写结果 |
| src-tauri/src/model_client.rs | 请求、取消、超时、模型响应解析 |
| src-tauri/src/storage.rs | 关系表读写、增量保存和导入事务 |
| src/features/library/templates.ts | 模板页默认提供的优化模板 |

优化时将所选模板作为系统消息。模板使用 Mustache 的 originalPrompt、分隔符指令及 helpers.toJson 时先本地渲染，三花括号原样插入文本，用户提示词留空时使用默认改写指令。请求规则由 Rust 根据模式追加。模型直接返回自然语言或 Markdown，只检查非空与长度，不要求类型标记。双框请求只发送左侧原稿和模板；连续对话只携带最近一次独立优化之后的消息。每次成功回复保存请求模板快照、输入和输出，聊天回复同时更新右侧优化稿。API Key 按供应商和接口地址保存，只由 Rust 读取；请求发送至所选端点。

## 验收顺序

1. 先实现可运行的工作台，验证每种页面状态、中文输入法、键盘操作、字体、窄窗口和两套主题。用截图检查布局。
2. 跑通 DeepSeek 与智谱 GLM，验证取消、超时、重试及切换稿件后迟到响应。
3. 检查重启恢复、搜索、聊天恢复、备份回导、损坏导入回滚和完整数据恢复。
4. 在干净 Windows 环境验证安装、启动和卸载。Gitee 发行版附源码、中文 README、许可证和 Windows 安装包。

系统内置仅保留基础分类下的「基础优化」「专业优化」「步骤化规划」。模板规定优化方向，程序统一追加首次生成与连续修改规则。连续对话默认沿用本段会话的模板快照；用户在输入框主动选择其他模板后，下一轮使用新模板并保留消息历史。模板优化使用当前选择的模板。双框选择模板并确认优化，从左侧原稿开启新一轮。

通过侧栏新建草稿时，草稿默认未分配项目；从项目页新建的草稿直接归入对应项目。草稿页顶部可以分配或清除项目。未命名草稿首次点击优化时用原稿开头自动生成标题。

## 常规设置与窗口行为

- 常规设置按主题样式、窗口行为、自定义快捷键排序。主题选项使用 16px 图标与 6px 图文间距，统一 34px 控件高度。
- 应用内快捷键使用物理按键 code 保存，支持 Ctrl/Alt/Shift 组合；录制中暂停其他快捷操作，校验系统保留按键和应用内冲突。配置保存在工作区 SQLite，默认使用 Ctrl+N 和 Ctrl+Enter。运行 `node tests/shortcuts.mjs` 验证规则（Node 22.18+）。
- 关闭行为保存为 ask/hide/exit，默认值为 ask。标题栏、Alt+F4 统一触发关闭处理；确认框支持记住选择。保存失败不隐藏、不退出，隐藏前检查托盘可用性。退出前提示正在进行的优化任务会中断。
- 托盘提供打开与退出入口，左击重新显示并聚焦原窗口。单实例插件避免重复启动多个工作区实例。
- 开机自启使用 Tauri 官方插件查询和修改系统注册状态，不随工作区备份迁移，不在启动时擅自开启。

## 系统内置与用户模板

- 基础分类及三个默认模板定义在 `src/features/library/templates.ts` 与 `upstream/builtin-templates.json`，分类不能编辑或删除，系统模板只读查看与预览。
- SQLite 的 `templates` 只保存用户模板。使用和展示时合并代码内置模板，优先保留内置 ID，禁止用户保存、删除或覆盖系统模板。用户可以在任一分类中新建自己的模板。
- 使用 `node tests/templates.mjs` 验证内置只读、自定义内容保存及 ID 冲突保护。

## 自定义模型供应商

供应商选择页提供“自定义供应商”，按 OpenAI 兼容协议请求 `/chat/completions`，通过 `/models` 获取模型列表。用户填写接口基础地址、API Key 和模型 ID，官方网站可选。模型支持手动输入和接口获取；自定义配置与预设配置一样支持连接测试、编辑、删除及草稿页选择。身份使用 `preset-custom`，不会因接口地址变更而从供应商列表消失。

## SQLite 当前结构

数据库位于应用数据目录的 `prompt-draft.sqlite`，由 `src-tauri/src/schema.sql` 直接初始化。包含十一张业务表与一张缓存表：

| 表 | 职责 |
| --- | --- |
| `projects` | 项目名称和创建、更新时间 |
| `drafts` | 草稿原稿、优化稿、项目归属、置顶与收藏 |
| `draft_messages` | 按稿件和顺序逐条保存问答，消息 JSON 包含正文、模板快照、模型及独立优化起点 |
| `draft_dialogues` | 仅保存模式和未发送的聊天输入，不保存消息正文或版本分支 |
| `template_categories` | 用户模板分类 |
| `templates` | 用户模板及系统、用户两段提示词 |
| `providers` | 供应商配置、默认模型、获取的模型列表及 API Key |
| `usage_records` | 请求结果、Token、接口范围和人民币费用快照 |
| `model_prices` | 内置、同步和用户覆盖价格 |
| `pricing_settings` | 汇率及价格同步状态 |
| `app_settings` | `preferences_json` 保存偏好，`ui_state_json` 保存当前稿件及侧栏展开状态 |
| `models_dev_cache` | models.dev 原始目录 JSON 与获取时间 |

日常保存通过 `workspaceChanges.ts` 计算实体差异，调用 `save_changes`，只传递变化的记录及删除 ID；Rust 在同一事务内更新相关表。UPSERT 对相同数据不执行写入。设置改变不会重写草稿，编辑草稿不重写其他草稿，未变化的消息记录也不写入。启动时将关系表组装为前端工作区，完整快照仅用于页面内状态和导入导出，不再作为数据库存储形式。

项目删除通过外键将草稿改为未分配，草稿永久删除则级联清除聊天消息及输入状态。模板分类可能指向代码内置分类，因此由 Rust 校验分类引用，并禁止用户覆盖内置 ID。供应商删除连同密钥一起生效，但请求记录保留独立的供应商 ID、名称和费用快照，不级联删除历史用量。

供应商名称、接口和密钥在 `providers` 同一行。Rust 查询工作区时明确选择非密钥字段，常规查询不包含 API Key；完整 JSON 备份由 Rust 直接写文件，包含 API Key 和全部 12 张表。更新配置时仅在接口地址未变时保留密钥，地址改变则清空；在请求时同时按 ID 与接口匹配密钥。

`model_prices.layer=base/override` 区分基础价格和用户覆盖；来源与同步时间直接保存在价格行。`usage_effective_prices` 是查询视图。价格、汇率、人民币成本用 TEXT 存储十进制数，Rust Decimal 计算；`cost_cny` 与 `cost_details_json` 一起保存历史金额，后续调价不重算已计价请求。Token 未提供保存 NULL，明确为零才保存 0。

数据库所有 `_at` 字段使用 Unix 毫秒时间戳。统计 IPC 保持秒级时间范围和时间展示，在 Rust 查询边界转换。原稿和优化稿在前端使用的模板及 API 协议保持不变。

测试阶段仅支持当前结构，不提供数据库迁移或旧版数据兼容；结构调整后直接重建测试库。系统模板始终从源码读取，不写入用户模板表。`cargo test` 与 `node tests/workspace-changes.mjs` 验证增量保存、事务回滚、密钥排除、删除关系及价格统计。

## 单窗口草稿并发

不同草稿可以独立发送优化请求，同一草稿处理中禁止重复发送。切换草稿或工具页面不终止请求，流式输出、取消和结果按草稿 ID 与请求 ID 隔离。侧栏中每个正在处理的草稿右侧显示加载动画。后台失败提示包含草稿名称；成功结果保留正文覆盖保护，编辑过的内容不会被覆盖。删除草稿或项目时取消涉及的请求，退出时处理全部请求，隐藏到托盘继续生成。完整备份和恢复仍需等待全部请求结束。不新增应用内并发数量上限，实际受供应商限制；不涉及多窗口同步。

## 草稿菜单与快捷键

标题菜单与右键菜单分别配置，提供重命名、置顶、收藏、复制草稿、项目归属与删除。菜单显示操作已绑定的快捷键。复制草稿只保留正文和项目归属，不复制聊天记录、收藏、置顶或活动请求。删除位于菜单末尾，确认中展示稿件和全部聊天记录的影响范围。不提供版本历史或恢复操作。快捷键仅作用于当前稿件，中文输入法组词、弹窗及录制期间不触发。


## 两种提示词修改方式

同一稿件支持「模板优化」与「连续对话」，模式和未发送输入保存在本机。生成期间可切换模式，等待回复时聊天输入框仍可编辑，同一稿件按顺序发送请求。

模板优化使用双框：左侧原稿，右侧当前优化稿，底部为模板、供应商、模型和确认优化。每次只基于原稿独立生成，成功后将原稿请求及完整结果追加到聊天记录，保存模板、模型和时间，并更新右侧。生成期间可编辑原稿，已发送的请求使用提交时的原稿，成功后直接更新右侧优化稿，之前的结果仍可在聊天中查看。失败或取消时保留上次的优化稿。

连续对话显示该稿件的所有记录，包括每次双框优化。独立优化前显示居中的上下文分隔提示；模板、供应商和模型变更在下一次发送时提示，同次变更合并为一条，详情悬停查看。用户可往上回看并复制旧结果；界面不提供版本编号、切换或恢复。新请求只使用最近一次独立优化及其后的消息，不发送前一段方案的讨论。没有双框优化时从最初的聊天继续。

模型直接回复，不要求讨论／稿件分类或 JSON 包装。聊天回复追加到记录，并更新右侧优化稿。请求带上当前段历史；手动编辑原稿或右侧正文后，在下一次追问中补充最新参考内容。模板改变只影响下一次成功请求，不清空消息。

发送后立即显示用户消息并清空输入框；AI 回复逐步显示。完整成功后保存问答，失败或取消不写入半轮记录；输入框为空时恢复发送内容，不覆盖等待期间新输入。正在输出的部分内容仅在内存中，退出后不能恢复。

`draft_messages` 按稿件 ID、消息 ID 和顺序保存，每条消息独立一行；`data_json` 仅包含该条消息。用户消息保存本次请求的上下文快照，`context.mode=draft` 表示独立优化起点。`draft_dialogues` 只保存模式和未发送输入。数据库事务原子保存一轮问答，增量 UPSERT 不重写旧消息，备份包含全部记录并校验角色、顺序、长度、模板和归属。删除稿件时级联删除消息。

模型请求最多 99 条消息，模板与正文合计最多 120,000 字，超限提示在双框重新优化开启新一轮，旧记录仍可回看，不静默截断。数据库历史记录不受单次请求轮数限制，供应商的 Token 上限可能更低。

测试阶段只维护当前数据结构，不提供旧结构或旧备份兼容；测试使用独立临时数据库，不自动清空用户数据库。

聊天消息交互：助手标题显示「用时」，底部提供复制、下载、放大、消息日期时间及字数。用户消息的复制和日期时间在悬停或键盘聚焦时显示，触屏保持可见。复制用户消息使用显示正文，不包含内部模板包装。不提供单条消息删除操作。数据库允许保留没有回复的提问，发给模型时仅取当前段中相邻的完整问答，不发送已删除回复及其未配对提问。

连续对话左侧提供消息刻度导航，每次用户提问对应一个刻度，所有刻度默认等长，只有悬停或键盘聚焦时加长。悬停或聚焦可预览提问及紧随其后的回复摘要，点击定位对应提问；当前视口中可见的提问对应刻度变深，可同时高亮多个；没有提问可见时不强制选中某一轮。长导航自动使可见刻度保持可见。支持键盘聚焦、Escape 关闭预览，并尊重系统减少动画设置。不改变保存内容和上下文分段。
